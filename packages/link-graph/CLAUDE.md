# @webtrax/link-graph

What a site's links say about it, from one run (C06.9 slice d, `plan/06-check-suites/link-ledger-and-insights.md`). Pure, with no runtime dependencies (protocol types only), so the cloud's app-api bundle can import it. The local MCP (`webtrax mcp`) reads it from `run.ndjson`; app-api reads it from a scan's `graph.json`. Both must give the same answer: `services/app-api/test/link-graph-parity.test.ts` checks it on the fixture site.

- **`LinkGraph`:** pages (in the order of the page records), page-to-page `links` as index pairs (one per pair, self links dropped), `siteWide` (pages linked from more than half the pages, on sites of 8 or more) and `targets`: broken targets and internal targets reached through redirects (`isInterestingTarget`), with their source pages as indexes; at most `TARGETS_MAX`, broken first, `TARGET_SOURCES_MAX` sources each. `targets: null` means the source had none (maps stored before 2026-11-24).
- **`buildLinkGraph(pages, links, meta)`** from page and `link` records; **`graphFromRun(records)`** from a whole run (the first page record is the start page). A page is also found by its final URL, as in the worker's `buildGraph`.
- **`impactOfChange(graph, paths, view?)`** (F-G13): moved here from app-api unchanged. `view` lets the cloud add its map's page fields; the default gives path, status and clicks from start.
- **`redirectDebt`** (F-A25): internal links whose target answered with redirects and then a working page. Hop times come from the engine (`redirect_chain[].ms`, wire time without throttle waits); a hop without one makes `redirect_ms` null.
- **`brokenLinkReach`** (F-E12): broken targets (the engine's `outcome`, so could-not-verify is never here) with how each source page relates to each key page: `on_page`, `on_route` (on a shortest route from the start page to it) or `one_click`. Any relation escalates. With no key pages it suggests up to five from `KEY_PAGE_HINT`.
