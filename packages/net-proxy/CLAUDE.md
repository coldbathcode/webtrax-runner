# @webtrax/net-proxy

Egress proxy for the browser stage (C05.10, SEC-03). `startEgressProxy({ policy })` listens on 127.0.0.1; `chromiumProxyArgs(url)` are the flags the browser stage launches Chromium with: all traffic through the proxy, loopback included (`--proxy-bypass-list=<-loopback>`), no name resolution in Chromium (`--host-resolver-rules=MAP * ~NOTFOUND`), no direct WebRTC UDP, no QUIC.

- CONNECT (HTTPS and WebSockets) and plain-HTTP requests are both checked: the proxy resolves the name, checks **every** answer with the same `ScopePolicy` as `@webtrax/net-guard` (so cloud metadata is always refused), and connects to the address it checked. Rebinding and mixed answers fail.
- `allowedPorts` limits which ports a page may reach; `refused` records every refusal (target and reason).
- Tests drive raw CONNECT/HTTP and a real Chromium (playwright-core): a page that tries to load a private address and the metadata endpoint still renders, and both are refused. Rules are mutation-checked.
- **Line shaping (`shape`, C06.10):** `shapedLine(kbps, delayMs)` makes transforms that share one rate per direction and hold each chunk for half the round trip; with `shape` set, every tunnel and plain-HTTP exchange goes through them, so each engine behind the proxy gets the same line. Unset, it is a pass-through.
- **Other engines (C06.10 slice d):** `browserLaunchOptions(engine, proxyUrl)` is how the browser stage launches each engine behind the proxy: Chromium by `chromiumProxyArgs`, WebKit and Firefox by Playwright's `proxy` with nothing bypassed, Firefox also with `FIREFOX_PROXY_PREFS` (loopback through the proxy, no DNS prefetch, speculative connections or DNS over HTTPS, no WebRTC, no HTTP/3). The canaries run for all three (`describe.each` in `test/proxy.test.ts`): private and metadata refused, `127.0.0.1` and `localhost` do not bypass, names resolve only in the proxy. Playwright already sends Firefox's loopback through the proxy (the canaries pass without the prefs); the prefs are a second layer for what the canaries cannot see. CI installs WebKit and Firefox (`scripts/ci/lib.sh`, the public `ci.yml` and `release.yml`).
