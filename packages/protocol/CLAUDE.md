# @webtrax/protocol

The runner protocol (C05.1): one definition of every record a run produces and the job spec that starts it. Apache-2.0; part of the open source runner (`runner/`, ADR 0010), consumed by the cloud for ingest (C04.5).

- `src/schemas.ts`: Zod schemas and types: `JobSpec`, `RuleMeta`, and the NDJSON `RunLine` union (`run`, `page`, `finding`, `metric`, `snapshot`, `artifact`, `link`, `summary`). `link` (2026-11-24, C06.9): one per link target, written before the summary, with the engine's outcome and its source pages; readers from runner 0.1 refuse those lines. `RedirectHop.ms` is optional. snake_case on the wire, like the database.
- `src/enums.ts`: suites, severities, run statuses, fetch and run errors. `suite` and `severity` must match the database enums in `packages/db/migrations/0001_baseline.sql` (a cloud-side test, `packages/db/test/protocol.test.ts`, reads the migration; the runner never reads files outside `runner/`).
- `src/fingerprint.ts`: `fingerprint(ruleId, url, evidenceKey)`, sha256 over the normalised URL (Web Crypto, async). Never put timings or ordering in the key.
- `src/url.ts`: `normaliseUrl`, with v1's semantics (fragment dropped, trailing slash removed except at the root).
- `src/bot.ts`: the WebtraxBot identity. No imports: v1 imports this file by path. `@webtrax/domain/bot` re-exports it.
- `schema/*.json`: JSON Schema generated from the Zod schemas. After changing a schema run `pnpm gen:schema`; a test fails on drift.
- **Changing a record:** additive changes only (new optional fields). A breaking change needs `PROTOCOL_VERSION` bumped and a note in the plan.
- Stays `"private": true` until the alpha release (C05.9) publishes it to npm.
- `src/score.ts` (also `@webtrax/protocol/score`, which imports no Zod, for the cloud app's browser bundle): **Health Score v2** (C06.8, D20). `healthScore({findings, pages, suites})` gives the same integer for the same inputs everywhere: per suite that ran, each (rule, severity) costs its severity weight times its breadth (1 site-wide, else min(1, 10 × places / pages checked)); suite score 100 × exp(−penalty / 12) to one decimal; the weighted average, rounded, with grades A to F. New in v2: `performance` and `a11y` (`SCORE_PER_DEVICE`) are judged against the pages they looked at in a browser (`suites[].pages` from the summary), and when a run measured several browser profiles each is scored per device (a finding's `by_profile`, from `evidence.severity_by_profile`) and the suite takes the mean (`devices` on its score). A run with no browser suite scores as in v1. Only `SCORED_PROFILES` (Chromium's `desktop` and `phone`) are scored: WebKit and Firefox profiles (C06.10 slice d) are left out, and with one scored device a finding counts at its severity there, or not at all if seen only elsewhere; scores of every earlier kind of run are unchanged. The constants are published in the docs (`/health-score/`) and pinned by `test/score.test.ts`: changing one means a new `SCORE_VERSION` and that page updated.
