# runner/ (open source, Apache-2.0)

The Webtrax runner, CLI and local MCP server (MASTER_PLAN C05). Public since the alpha as `coldbathcode/webtrax-runner` (ADR 0010, D16). **This directory stays the source of truth** (ADR 0011): commit here, then `scripts/sync-runner.sh --push` mirrors each commit that touched `runner/` to the public repo with the standard workspace files added. Never commit to the public repo directly (the sync refuses when its HEAD matches no commit here). Keep runner commits separate from other work: their messages become public, and the sync refuses messages with an email address or a private identifier. The ordered steps, with what to read and "done when", are in [`plan/BUILD-PLAN.md`](../plan/BUILD-PLAN.md) Phase 1; status is in `TRACKER.md`.

- **Imports nothing outside `runner/`:** no cloud package (`@webtrax/domain`, `@webtrax/db`, `@webtrax/config` …), no relative path, tsconfig or file read that climbs out. `test/independence.test.ts` enforces it. Shared things the cloud also needs (protocol, bot identity) live here and the cloud imports them.
- **Own toolchain:** `tsconfig.base.json` and `eslint.base.js` here; packages extend `../../tsconfig.base.json` and use `runner()` from `../../eslint.base.js`. Every `package.json` says `"license": "Apache-2.0"` (tested).
- **Packages:** `packages/<name>`, published as `@webtrax/<name>` at the alpha. They stay `"private": true` until C05.9. The executor is `@webtrax/engine` (`@webtrax/core` is the cloud's).
- **Behaviour reference:** v1's crawler in `apps/legacy/runner/lib/` (`crawl-core.js`, `address.js`, `guarded-fetch.js`) and its tests. Port semantics exactly unless the plan says otherwise.
- **Commands:** `pnpm --filter './runner/**' test`, or `pnpm run check` at the root (the pre-push hook) which includes these packages.
- **Public-repo files, dormant here:** `action/` (the GitHub Action, tested in the monorepo CI against the fixture with the local CLI build), `.github/workflows/ci.yml` and `release.yml`. GitHub only reads the monorepo's root `.github`, so they run in the public repo only.
- **Container image** (`Dockerfile`, H1): `scripts/image.sh [tag]` packs the CLI and builds on the Playwright base image that matches `playwright-core` (bump both together); `scripts/image-test.sh [tag]` proves it: version, non-root, and a `--browser` fixture check inside it (read-only root, no network) gives the same findings as outside. Both CIs run them. Not published to a registry yet (C05.11: multi-arch, cosign, SBOM, Trivy).
- **Releasing:** bump `packages/cli/package.json`, commit, sync, then push a `vX.Y.Z` tag to the public repo. `release.yml` checks, builds, publishes to npm with provenance, moves the major tag (`action@v0`) and creates the GitHub release.
